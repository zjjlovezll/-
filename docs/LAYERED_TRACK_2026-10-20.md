# 分层轨道（layered track）：钢轨 / 扣件 / 轨枕 / 板下胶垫 / 轨道板

日期 2026-10-20。这一节交付的是**软件能力**而不是某一次标定：轨道层数变成算例输入，
用户第③阶段要求的那套结构（钢轨、扣件、轨枕、板下胶垫、轨道板）现在可以按图纸逐层配。

## 1. 配置方式

```json
"track_dynamics": {
  "kind": "layered",
  "layers": [
    {"mass_y_kg": 79,  "mass_z_kg": 79,  "k_y_n_m": 6e6,  "c_y_n_s_m": 60e3,
     "k_z_n_m": 12e6,  "c_z_n_s_m": 120e3},          // 轨枕，下面的弹簧=道床
    {"mass_y_kg": 300, "mass_z_kg": 300, "k_y_n_m": 25e6, "c_y_n_s_m": 200e3,
     "k_z_n_m": 50e6,  "c_z_n_s_m": 400e3}           // 轨道板，下面的弹簧=路基
  ]
}
```

`rail_templates[i].support` 始终是**扣件/胶垫**（钢轨与第一层之间的弹簧）。`layers[i].k/c`
是第 i 层**下面**的弹簧，所以：

| 层数 | 物理栈 | 与既有模型的关系 |
|---|---|---|
| L=0 | 钢轨 —扣件→ 地面 | 等价于 `local_compliant` |
| L=1 | 钢轨 —扣件→ 轨枕 —道床→ 地面 | 等价于 `two_layer` |
| L=2 | 钢轨 —扣件→ 轨枕 —垫层→ 轨道板 —路基→ 地面 | 新增（无砟道岔的完整栈） |

自由度按轨排列：`(y_rail, z_rail, y_L1, z_L1, y_L2, z_L2, …)`，起始下标 35，
跨度 `2*(1+L)`；总自由度 `35 + 2*(1+L)*轨数`。

## 2. 回归：L=1 与 `two_layer` 逐项一致

`validation/crh380a_m/case_AB_equiv_two_layer.json`（同一套参数，kind 换成 `layered`）：

| 量 | two_layer | layered L=1 | 差 |
|---|---|---|---|
| 峰值（右轨） | 106.76 kN | 106.90 kN | +0.13% |
| 最小力 | 23.33 kN | 23.21 kN | −0.5% |
| 轮对行程 | 0.1009 mm | 0.1011 mm | +0.2% |
| 主频 | 633.66 Hz | 633.66 Hz | 0 |

差异来自力组装顺序不同导致积分器步长序列不同（nfev 38 561 vs 37 481），不是物理差异。

## 3. 加上轨道板之后：低频带回来了

同一辙叉窗（0.05 s），只改层数：

| 算例 | 峰值 | 最小力 | 轮对行程 | 主频 | 30-60 Hz | 150-250 Hz |
|---|---|---|---|---|---|---|
| 刚体轨道 | 158.04 kN | 3.02 | 0.5933 mm | 175.76 Hz | 1.183 | 6.402 |
| L=1（轨枕+道床） | 106.90 | 23.21 | 0.1011 | 633.66 | 0.802 | 0.859 |
| **L=2（+轨道板+路基）** | **108.83** | 23.26 | **0.1662** | 633.66 | **1.133** | 0.871 |
| Simpack（同段） | ~128 | 27.67 | 0.5944 | 31.65 | 4.839 | 1.088 |

- 加一层之后 30-60 Hz 从 0.802 回到 **1.133**（+41%），轮对行程从 0.101 提到 0.166 mm
  ——**分层确实把低频运动还回来了**，与 S1-f 第 9 节的判断一致（缺的是低频参与质量）。
- 但主频仍是 **633.66 Hz**，即轮对压在接触弹簧上的振铃；层数增加没有改变它。

## 4. 因此剩下两件事（都不在轨道层）

1. **633 Hz 振铃**：接触阻尼按 Simpack `fn.dref=1e5` 的口径定标，而不是继续调恢复系数 `e`。
   判据：150-250 Hz 带绝对 RMS 下降到 1.1 kN 量级（参考值），且峰值不升高。
2. **31.65 Hz 主导**：参考解的轨道在接触点有更大的低频参与质量（道床锥体 + 轨道板连续质量），
   我们的逐支承集总只给到 300 kg 级；要完全对上需要把轨道板按**连续**结构建（S1-g 第二刀）。

## 6. 模态轨：为什么现在还不能用在道岔上（第 34 轮排查）

为了拿到**沿里程分辨的钢轨响应**（轨道截面加速度、轨底应变的前置条件），我回到已有的
`track_dynamics = {"kind": "modal"}` 路径，排查它能否直接用于本道岔算例。结论是**不能，且原因在
数据结构而不在数值**。

`validation/crh380a_m/probe_modal_layout.py` 实测（`track_modes_turnout.json`）：

- 60 阶模态，`phi_z` 形状 (60, 251)，站位 0–150 m；`phi_y` 全零 ⇒ **只有垂向弯曲**；
- `phi_z[i]` 是余弦型驻波，60 阶频率全落在 131.93–156.00 Hz ⇒ 这是"整根轨在 N 个扣件上浮沉"
  的同一支带，不是从低频到高频的完整模态谱；
- `stiffness_n_m` / `damping_n_s_m` 是**长度 60 的向量**（每阶一个），不是矩阵。

决定性问题在 `track_models.py:229`：模态内力作用在 `q[35:]` 上，即**全部钢轨共用一套模态坐标**。
道岔里左右轨必须独立运动（右轨踩辙叉、左轨不参与），共用一套坐标等于把两根轨焊成一个物体。
因此我把 `load_modal_track` 的真值报错写清楚（`track_models.py:75-88`）：指出"单套模态坐标"
这条限制，并指向 `layered`。这不是"文件不匹配"，而是"这条路不能表达道岔"。

⇒ 下一步（明确、可回归）是把模态块改成**每轨一套**：
`q[35 + mode_count*i : 35 + mode_count*(i+1)]`，与 `layered` 现在的 `35 + 2*(1+L)*i` 同构；
验收门用 `L=0/1` 的已冻结等价回归（`case_AB_equiv_two_layer.json`）先确认不改现有行为，再开关模态。
在此之前，`modal` 路径保持"可用但对道岔不适用"，并有测试守护这条边界（`tests/test_modal_contract.py` 4 项）。
