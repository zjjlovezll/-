# 曲线缺口到底是不是"算法不够好"：把接触能提供多少横向力量出来

日期：2026-10-28。上一轮把曲线失败归到"`creep_stiffness_lateral_n = 5.0e5 N` 比物理值低一个数量级"，
用户随后问了一个更尖锐的问题：**会不会其实是算法（而不是物理）不够好？**
这一轮把问题改写成可以直接量的形式：**在八个轮子仍然落在钢轨顶面、载荷仍在验收带内的前提下，
这个接触模型最多能提供多少横向力？** 需求是 `m v²/R = 21 842.4 N`（R = 1100 m、80 km/h、48 654 kg）。

## 1 两种读法，先分开

同一个 `--creep-scale 10`（`f22` 由 5.0e5 提到 5e6）结果可以读成两件完全不同的事：

| 读法 | 含义 | 如何区分 |
|---|---|---|
| **A 方向错** | 力产生了，但指向不对，加大增益只是更快走错 | 看"给定几何下接触自己的横向力"与需求的比值 |
| **B 初始条件错** | 初始态与新 `f22` 不自洽，瞬态冲进轮缘 | 看"有没有一个满足全部约束的静态/准稳态解" |

两种读法都给同一个预言（都是更早失败），所以必须另找一个不依赖轨迹的量。
**能力曲线**就是这个量：横向行不解，只把轮对横移与冲角**指定**，在每个几何上重解竖向行，
然后读接触自己算出来的净横向力。

## 2 先量框架平衡：它不存在

`scripts/s43_running_equilibrium.py` 的第一段：沿用今天的静平衡（只解 z，曲线上再加轮对 yaw），
然后打印它**没有**解的那些横向行：

```
seat residual 1.022e-07 N
eight rails 59 680.5 .. 60 417.7 N (0.988 .. 1.013x), pen 65.47 .. 65.50 um
sum N 477 444.4 N (1.000x weight)      sum Fy +2 090.7 N (+9.6 % of demand)
the lateral rows it does not solve: |max| 15 683.1 N
```

也就是说今天的座只保证竖向干净，**它返回的状态里 15.7 kN 的横向力是没人承担的**。

把 `y / roll / yaw` 一起放进未知量（9 个种子，`xtol`，barrier 命中 0）：

```
best |r|max 8.4124e+03 N   cond 1.505e+04
sum N 477 450.7 N (1.000x)   sum Fy -1 391.3 N (-6.4 % of demand)
wheelset y [-0.822 -2.584 -1.107 -2.938] mm   yaw [0.455 0.727 0.376 0.832] mrad
VERDICT NOT FOUND
```

残差下限 8.41 kN 停在 21.84 kN 需求的 38 % 处，且**没有任何一个种子接近 0.1 N**。
但"解不出来"也可能只是我的求解器不好（cond 1.5e4 不算病态，可 xtol 停住也说明它撞到了某个面）。
所以这一段**不能**当作结论，只能当作"需要能力曲线"的动机。

## 3 能力曲线（这一轮的实质）

`capability_sweep(...)`：给每个轮对指定横移 −4.00…+4.00 mm（0.5 mm 步长）与冲角 0/+1/+2 mrad，
在每个几何上只重解竖向行（所以载荷仍是 477 kN），读接触自己的 `sum Fy`、每轮载荷比与最大侵入。
51 个状态，全部竖向残差 1e-08…1e-07 N。

| 0 | −2.00 | +12 472.5 | +57.1 % | 0.047–1.953 | 出带 | 105.52 |
| 0 | −1.00 | +7 874.3 | +36.1 % | 0.451–1.549 | 出带 | 85.04 |
| **0** | **−0.50** | **+4 471.4** | **+20.5 %** | **0.738–1.263** | **在带** | 76.82 |
| 0 | 0.00 | +2 090.7 | +9.6 % | 0.988–1.013 | 在带 | 65.50 |
| 0 | +0.50 | −296.7 | −1.4 % | 0.750–1.251 | 在带 | 76.98 |

两条读数，都是"先定判据再跑"的结果：

1. **验收带内的横向力上限是 8.17 kN = 需求的 37.4 %**（冲角 +2 mrad、横移 +0.5 mm、
   每轮 0.750–1.251、侵入 77 µm）。在带内无论怎么组合都到不了 21.84 kN。
2. **需求只有在"整侧卸载"时才出现**：+4 mm / +2 mrad 给出 22.28 kN（102 %），
   但比值 0.000–2.002；因 `sum N` 仍是 1.000× 重量，`4×0 + 4×2.002 = 8.008`，
   即**四个轮子完全离开钢轨、另外四个承担两倍**。

## 4 这个"整侧卸载"是不物理的——差 2.7 倍

真实车辆在曲线上靠超高承担大部分横向力。无超高时，载荷转移由横向力对质心的力矩决定，
取质心高 h ≈ 1.5 m、半轨距 b = 0.7465 m：

```
ΔP = F_lat · h / b = 21 842.4 × 1.5 / 0.7465 ≈ 43.9 kN   ->   ±21.9 kN  (0.63x .. 1.37x)
```

即**真实**需要的载荷转移是 0.63×…1.37×，落在验收带 [0.625, 1.6] 内；
而模型要到需求必须卸载 ±59.66 kN（0.00×…2.00×），**是物理值的 2.7 倍**。

模型的横向力单位载荷产出因此是 **1.7 %（带内 8.17/477）**，要到需求必须 **4.7 %**；
真实曲线需要的正是 **4.6 %**。缺的这 2.9 个百分点不是数值精度，是**接触平面倾角/蠕滑的物理内容**。

## 5 这回答了什么、没回答什么

**能回答的**：曲线缺口**不是反演算法**（反演根本没开始跑），也**不是**"把 `f22` 调大"能解决的
（`--creep-scale 10` 更早失败，现在有了机制：它把力放大但方向仍由那 2 % 的接触平面倾角决定）。
在没有超高的 R=1100 m / 80 km/h 上，**"八轮着地且每轮在带内"与"提供 21.8 kN"是互斥的**——
这是这一轮最硬的一句话，也是为什么第 4 段目标一直被标成降级而不是调参。

**不能回答的**：接触平面倾角为什么固定在 ±0.0250。轮对的横移在带内只允许 ±0.5 mm，
所以这个倾角几乎没有机会随位移演化；若它在真实轮轨上随横移快速变化（锥度、轮缘根部、两点接触），
那么"带内上限 8.17 kN"就会被抬高。这一条**必须用独立测量**（不同横移下 `n_y/n_z` 与 `lever_y`
的演化）来判定，而不是靠参数。下一步就是它：**接触几何随横移的敏感度**，而不是再解一次平衡。

## 6 预注册的下一步（判据先写死）

| 实验 | 判据 |
|---|---|
| `n_y/n_z` 与 `lever_y` 对横移（−3…+3 mm，0.25 mm 步长）的演化 | 若 `d(n_y/n_z)/dy` 能把带内上限抬到 ≥ 1.0× 需求，则"带内不可能"这一条被推翻，需要改的是接触几何而不只是超高 |
| 超高（107 mm）进几何与力 | 在带内 8/8、每轮 ∈[0.625,1.6]×、`sum Fy` ≥ 0.9× 需求；`cant = 0` 逐位不变 |
| 两点/轮缘接触作为**新物理**（需授权） | 只允许在既有斜率门内由几何判定产生，**不得**放宽 `maximum_abs_contact_slope` |
