# 把降低值装进算例：双体尖轨区（2026-10-29，第 213 轮）

## 0 这一轮补的是哪一步

P1 要的是「真值来自设计几何本身」：零不平顺跑一趟 → 反演 → 与设计降低剖面比。上一轮（第 211 轮，`1070c98`）量清了一件 unpleasant 的事实：**算例的站表里没有降低值**——右侧站表在 stock / `qjbg`（曲基本轨）/ `qjg`（曲尖轨）/ `cxg`（心轨）之间切换的是**用哪一个断面**，不是**它有多低**；同一里程只有一根轨存在，所以 23 mm 的降低值无处安放。同时那一轮也证明了**机制**是通的：把 `z_offset_m` 加在站表上，冠高就真的跟着降。

这一轮把「机制通了」变成「数据里有了」：把尖轨区改成**双体**（基本轨 + 尖轨），尖轨按 `Cal_RailBeam_230518.m` 的 `InpRail.Pos_Z.R2_zjg` 表（`reports/turnout_lowering_2026-10-29/lowering.json`）逐站降低。

## 1 为什么双体是唯一合法的表示

真实道岔在尖轨区**两根轨同时在**：

* 车轮坐在**基本轨**上（这是走行面）；
* 尖轨从 23 mm 深逐步抬起，抬到与基本轨齐平时才真正承力；
* 车轮的竖直位移因此是**设计降低剖面本身**——它由几何决定，不需要任何不平顺文件。

单体的表示做不到这件事：同一里程只有一根轨，要么它有降低值（车轮掉下去 23 mm，物理上错），要么没有（降低值消失，P1 的真值就没了）。

装载器早就支持双体：`src/velch/vehicle.py:433` 接受 `rail_templates[i]["bodies"]`，每个体有自己的 `stations`、`s_lo_m`、`s_hi_m`、`y_window_m`。所以这是**算例构建**，不是求解器改动。

## 2 映射口径（写死，不靠猜）

设计表按「距 FSR 的距离」给，而本算例自己的尖轨区是 **60.95–70.92 m**（长 9.97 m，设计表长 10.96 m）。两个里程原点在现有数据里无法互校，所以：

* **把降低曲线的零点钉在本算例第一个 `qjg` 站**（60.95 m）；
* 形状用设计表的**距尖端距离**（0 / 0.578 / 2.889 / 5.28 / 6.569 / 7.304 m → 23 / 14 / 3 / 1.375 / 0.5 / 0 mm）。

±1 m 的原点平移会改变「转换发生在哪一段」，**不改变 23 mm 这个幅值**——而 P1 要检出的正是幅值。

## 3 实测：注入的几何与设计表逐点一致

`scripts/s52_switch_two_body.py`（`--side right`，默认读语料算例）：

```
side            right   blade zone 60.95 .. 70.92 m   stations stock 16664 / blade 1996

  crown datum (measured where the design lowering is zero): -0.061 mm

  mileage   stock crown   blade crown   gap    design    residual
     60.95      +0.072     -22.866   22.939   23.000    +0.000
     62.94      +0.072      -7.122    7.194    7.255    -0.000
     64.94      +0.072      -2.118    2.190    2.252    -0.000
     66.93      +0.072      -0.763    0.835    0.896    -0.000
     68.92      +0.072      +0.134   -0.061    0.000    +0.000
     70.92      +0.072      +0.134   -0.061    0.000    +0.000

worst |(gap - datum) - design| = 0.000 mm
VERDICT: the blade sits below the stock rail by the design lowering
```

两处必须说明：

1. **`crown datum = −0.061 mm`**：两套断面族各自在**自己的冠部基准**上数字化——设计表说「尖轨已全高」的位置上，stock 冠读 +0.072 mm、blade 冠读 +0.134 mm。这个常数与降低值无关，所以判据是「把这条常数拟合掉之后，剩余随里程的变化必须等于设计表」。不做这一步的话，0.061 mm 的数字化基准会被误报成形状误差（第一版就是这么报的 `worst 0.061 mm`）。
2. **residual 恒等于 0 是构造性的**：尖轨的冠 = 断面冠 − 设计降低值，而判据正是「基本轨冠 − 尖轨冠 − 基准 = 设计降低值」。所以这一行**验证的是注入算术与站表落地，不是验证设计表本身**。设计表是**真值**，不是被检对象；P1 要检出的是它。

## 4 边界（这一轮没有做的事）

* **没有跑时程**。前桥 P1 的下一步（零不平顺运行 → 反演）要穿过整个尖轨区（60.95–70.92 m），而车辆要在 50 m 附近起步，那里正是 B047（横向定位硬 927 倍）与 B045（`lever_y` 越出轨头）仍未清掉的区间。所以「双体几何能坐住、能跑到出口」这句话**现在不能说**。
* **尖轨形面本身仍是原断面族**：注入的是**整体竖向偏移**，没有按设计把尖轨头部做成变截面（`CN18-jg-0` 是 4.0 mm 宽的薄片，`CN18-jg-40` 已 43.9 mm）。这个差别在「车轮先在基本轨上、抬到齐平才承力」这条主效应上是一阶小量，但在尖轨真的承力之后的接触几何上不是。已登记为 P1 的下一步。
* **实测超差曲线没叠加**（`Choose_zjgUnEven == 1` 时那条 `[0,+0.9]…` 的实测偏差，会让末端不再归零）。P1 用**设计值**做真值，所以默认不叠；要模拟「实测超差」时再加。
