# 曲线缺口到底是不是"算法不够好"：把接触能提供多少横向力量出来

日期：2026-10-28。上一轮把曲线失败归到"`creep_stiffness_lateral_n = 5.0e5 N` 比物理值低一个数量级"，
用户随后问了一个更尖锐的问题：**会不会其实是算法（而不是物理）不够好？**
这一轮把问题改写成可以直接量的形式：**在八个轮子仍然落在钢轨顶面、载荷仍在验收带内的前提下，
这个接触模型最多能提供多少横向力？** 需求是 `m v²/R = 21 842.4 N`（R = 1100 m、80 km/h、48 654 kg）。

## 1 两种读法，先分开

同一个 `--creep-scale 10`（`f22` 由 5.0e5 提到 5e6）结果可以读成两件完全不同的事：

| 读法 | 含义 | 如何区分 |
|---|---|---|
| **A 方向错** | 力产生了，但指向不对，加大增益只是更快走错 | 看"给定几何下接触自己的横向力"与需求的比值 |
| **B 初始条件错** | 初始态与新 `f22` 不自洽，瞬态冲进轮缘 | 看"有没有一个满足全部约束的静态/准稳态解" |

两种读法都给同一个预言（都是更早失败），所以必须另找一个不依赖轨迹的量。
**能力曲线**就是这个量：横向行不解，只把轮对横移与冲角**指定**，在每个几何上重解竖向行，
然后读接触自己算出来的净横向力。

## 2 先量框架平衡：它不存在

`scripts/s43_running_equilibrium.py` 的第一段：沿用今天的静平衡（只解 z，曲线上再加轮对 yaw），
然后打印它**没有**解的那些横向行：

```
seat residual 1.022e-07 N
eight rails 59 680.5 .. 60 417.7 N (0.988 .. 1.013x), pen 65.47 .. 65.50 um
sum N 477 444.4 N (1.000x weight)      sum Fy +2 090.7 N (+9.6 % of demand)
the lateral rows it does not solve: |max| 15 683.1 N
```

也就是说今天的座只保证竖向干净，**它返回的状态里 15.7 kN 的横向力是没人承担的**。

把 `y / roll / yaw` 一起放进未知量（9 个种子，`xtol`，barrier 命中 0）：

```
best |r|max 8.4124e+03 N   cond 1.505e+04
sum N 477 450.7 N (1.000x)   sum Fy -1 391.3 N (-6.4 % of demand)
wheelset y [-0.822 -2.584 -1.107 -2.938] mm   yaw [0.455 0.727 0.376 0.832] mrad
VERDICT NOT FOUND
```

残差下限 8.41 kN 停在 21.84 kN 需求的 38 % 处，且**没有任何一个种子接近 0.1 N**。
但"解不出来"也可能只是我的求解器不好（cond 1.5e4 不算病态，可 xtol 停住也说明它撞到了某个面）。
所以这一段**不能**当作结论，只能当作"需要能力曲线"的动机。

两条读数，都是"先定判据再跑"的结果：

1. **验收带内的横向力上限是 8.17 kN = 需求的 37.4 %**（冲角 +2 mrad、横移 +0.5 mm、
   每轮 0.750–1.251、侵入 77 µm）。在带内无论怎么组合都到不了 21.84 kN。
2. **需求只有在"整侧卸载"时才出现**：+4 mm / +2 mrad 给出 22.28 kN（102 %），
   但比值 0.000–2.002；因 `sum N` 仍是 1.000× 重量，`4×0 + 4×2.002 = 8.008`，
   即**四个轮子完全离开钢轨、另外四个承担两倍**。

## 4 这个"整侧卸载"是不物理的——差 2.7 倍

真实车辆在曲线上靠超高承担大部分横向力。无超高时，载荷转移由横向力对质心的力矩决定，
取质心高 h ≈ 1.5 m、半轨距 b = 0.7465 m：

```
ΔP = F_lat · h / b = 21 842.4 × 1.5 / 0.7465 ≈ 43.9 kN   ->   ±21.9 kN  (0.63x .. 1.37x)
```

即**真实**需要的载荷转移是 0.63×…1.37×，落在验收带 [0.625, 1.6] 内；
而模型要到需求必须卸载 ±59.66 kN（0.00×…2.00×），**是物理值的 2.7 倍**。

模型的横向力单位载荷产出因此是 **1.7 %（带内 8.17/477）**，要到需求必须 **4.7 %**；
真实曲线需要的正是 **4.6 %**。缺的这 2.9 个百分点不是数值精度，是**接触平面倾角/蠕滑的物理内容**。

## 5 这回答了什么、没回答什么

**能回答的**：曲线缺口**不是反演算法**（反演根本没开始跑），也**不是**"把 `f22` 调大"能解决的
（`--creep-scale 10` 更早失败，现在有了机制：它把力放大但方向仍由那 2 % 的接触平面倾角决定）。
在没有超高的 R=1100 m / 80 km/h 上，**"八轮着地且每轮在带内"与"提供 21.8 kN"是互斥的**——
这是这一轮最硬的一句话，也是为什么第 4 段目标一直被标成降级而不是调参。

**不能回答的**：接触平面倾角为什么固定在 ±0.0250。轮对的横移在带内只允许 ±0.5 mm，
所以这个倾角几乎没有机会随位移演化；若它在真实轮轨上随横移快速变化（锥度、轮缘根部、两点接触），
那么"带内上限 8.17 kN"就会被抬高。这一条**必须用独立测量**（不同横移下 `n_y/n_z` 与 `lever_y`
的演化）来判定，而不是靠参数。下一步就是它：**接触几何随横移的敏感度**，而不是再解一次平衡。

```
d(n_y/n_z)/dy  +0.000 1/m      d(lever_y)/dy  +0.00000 m/m
tilt range 0.02350 .. 0.02498   best in-band |sum Fy| 4 471.4 N = 20.5 % of demand
VERDICT BAND STILL SHORT: geometry rate does not rescue it
```

**倾角对横移完全不响应**（斜率 6.9e-16，四舍五入为零），`lever_y` 也只动 2 mm。
倾角只取 0.02182/0.02238/0.02326/0.02328/0.02463/0.02498/0.02547 这几个离散值——
接触点在横向上是**跳格**的，不是连续的。

这给出一条**结构性上限**，比 §3 的"带内上限 8.17 kN"更强：

```
Fy <= sum(N_i * n_y_i) <= W * tan(tau) = 477 295.7 x 0.02498 = 11 922 N
demand                                                     = 21 842.4 N
```

即**整车的横向力被"冻结的 2.5 % 倾角"封在 11.9 kN，无论载荷怎么转移**（要 21.8 kN 就得
`ΔN = 872 kN > W`，物理上不可能）。带内实测 8.17 kN 是这个上限的 69 %。
蠕滑这一侧：`slip_lat ≈ 11 mm/s` → `f22·slip/v = 5e5×0.011/22.22 ≈ 248 N/接触`；
2 mrad 冲角 → `≈1 kN/接触` → 八个接触约 8 kN，与 +2 mrad 那几行一致。
**两条通道加起来仍不到需求的一半，而 21.8 kN 只有靠整侧卸载才出现。**

## 6c 所以缺的是"倾角随横移演化"这一层

真实轮对的横向力之所以能到 4.6 % 载荷，是因为在 4 mm 级横移下**接触点沿踏面移动、倾角随之改变**
（锥度、轮缘根部、两点接触）。本模型把它固定成 2.5 %，于是：
没有超高时，**曲线只能靠轮缘**——而轮缘被 `maximum_abs_contact_slope = 1.0` 挡住（这是项目规则，不许放宽），
超高才是正路，这也正是 18 号道岔与所有真实曲线都有 107 mm 超高的原因。
**"八轮着地、每轮在带内、无超高、提供 21.8 kN"在物理上互斥**，这一条现在有三处独立数字支持
（带内上限 8.17 kN、结构上限 11.92 kN、真实载荷转移只需 0.63×–1.37× 而模型要 0.00×–2.00×）。

## 6d 横向力到底由哪一项给：逐项分解（直接调用 `evaluate_contact` 对照）

上一节的"倾角给 54 %"只在**单接触**口径下成立；按左右成对求和，法向分量几乎完全抵消。
把座好的状态逐项拆开（`scratch/slip_terms.py`、`scratch/slip_direct.py`）：

```
axle1_left : lever_y -0.70732 lever_z -0.42982 normal (+0.02497,+0.99969) tangent (+0.99969,-0.02497)
             Fy +1755.9 N = N*n_y +1508.7 + Ft*t_y +247.3      Ft +247.3 N
axle1_right: lever_y +0.79823 lever_z -0.42982 normal (-0.02497,+0.99969) tangent (+0.99969,+0.02497)
             Fy -1222.3 N = N*n_y -1471.9 + Ft*t_y +249.6      Ft +249.6 N
```

- 法向项 `N·n_y` 左右**反号**（+1 508.7 / −1 471.9），净和只剩 +36.8 N；
- 蠕滑项 `Ft·t_y` 左右**同号**（+247.3 / +249.6），净和 +497 N；
- 所以**净横向力几乎全部来自蠕滑**，倾角只改变载荷分配。

`slip_lat` 的来源也钉住了：直接调 `evaluate_contact`（roll=0、spin=v/r、attack=0）得
`slip_lat = 0.00000000`，而 `evaluate` 内部同一接触给 `−0.01115896`——差值正是
`creep_attack_velocity_m_s = travel × q[yaw]`，`q[yaw] = −0.502 mrad`（座的 yaw 解），
`22.222 × 0.000502 = 0.01116 m/s` ✓。**不是伪蠕滑，是座自己选的冲角。**

## 6e 系数标度：`f22` 比 Kalker 量级低 5 倍，而"两个一起乘 10"必然失败（这条把 L13 用上了）

按 §6d 的链条：`yaw` 由**纵蠕滑偶**平衡悬架 `k_yaw` 决定（`f11·v·κ·b` 的力矩 ≈ 1.02 kN·m ÷ 1.96e6
= 0.52 mrad ✓ 实测 0.502），横向力再由 `f22·(v·yaw)/v = f22·yaw` 给出：

```
F_lat,net  ~  f11 * f22 * kappa * b^2 * v / k_yaw
我们的值      1e6 x 5e5 x 9.09e-4 x 0.556 x 22.22 / 1.96e6  ~  2.9 kN   （实测净 +2.1 kN）
Kalker 量级  f11 ~ 3.5e6 N, f22 ~ 2.5e6 N（60 kN 轮载、a/b ~ 0.3 的椭圆的线性蠕滑系数）
             -> F_lat,net ~ 70 kN，且会被 mu*N = 23.9 kN/接触 的饱和截住
```

这就解释了此前那次"两个系数一起乘 10 反而更早失败"（行程 2.05 m vs 4.53 m）：
`f11` 也乘了 10，纵蠕滑偶变 10 倍、`yaw` 被推到 5 mrad 量级，轮对**转过量**直接压上轮缘——
失败的是**偏转平衡**，不是横向力量级。**只放大横向而那一个 5 倍是不够的，两个系数必须各自回到
Kalker 量级并带 `mu·N` 饱和**（L13：CONTACT/FASTSIM/Polach 都按 `mu·N` 归一）。

预注册的下一步（需授权，属改接触律参数）：`f11 = 3.5e6`、`f22 = 2.5e6`、保留
`tangential_model = sditt_cubic_saturation`，其余不动；判据 = 0.34 s 内 8/8 轮着地、每轮
∈[0.625,1.6]×、`sum Fy` ≥ 0.9× 需求、七门全过；**若仍失败**则曲线项维持降级并把
"系数标定不足以救"作为结论写死。
