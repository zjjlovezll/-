# 曲线为什么停不下来：摇头平衡被量到闭合（2026-10-28）

本文记录目标第 4 项（曲线能力）在这一轮的唯一未验证候选 —— **轮对摇头平衡** —— 的实测结果。
它不是新的物理，也不是新的假设：所有数字都来自**坐在曲线站表上的那一个状态**里的一次 `evaluate`。

## 1 排除法走到了哪一步

前面几轮已经把候选逐个用测量排掉：

| 候选 | 判据 | 结论 |
|---|---|---|
| 几何路由不给向心力 | 八轮 60.4/60.2/59.1/58.9 kN 精确落座，随后 1.04 m 触发斜率守卫 | 排除（放置与接触都对） |
| 绝对航向被当成攻角 | 把每个刚体的 `yaw` 归零反而**更早**失败（40.76 m vs 41.04 m） | 排除（B042 已改为写 0） |
| 初始横向速度为 0 | 补 `_align_velocity_to_track`，失败点 1.04 m → 1.20 m | 部分（B043），但不是主因 |
| 缺横向/摇头阻尼 | 20 kN·s/m、20 kN·m·s/rad：0.60 s 过冲 151 % → 172.6 % | 排除（不改变走向） |
| 站表冠距 1.50667 m | 改成 1.4930 m 后静平衡**不收敛**（`gtol`） | 排除（那是标定参考构型） |

剩下唯一没量的就是：**这个几何到底能不能靠蠕滑把 21.8 kN 的曲线需求给出来**。

## 3 这条链可以逐项算出来，与实测逐位对上

| 环节 | 算式 | 数 |
|---|---|---|
| 曲率进入纵向蠕滑 | `Δv_x = κ v b` = (1/1100)·22.222·0.7465 | **0.0151 m/s** |
| 纵向蠕滑力 | `F_x = f11 · Δv_x / v` = 1e6 × 0.0151 / 22.222 | **680 N**（实测 1.04–1.08 kN 量级 ✓） |
| 力偶 | `2 F_x b` = 2 × 680 × 0.7465 | **1.02 kN·m**（实测 0.98–1.02 ✓） |
| 由此得到的摇头 | `1.02 kN·m / 1.96 MN·m/rad` | **0.52 mrad**（实测 0.50–0.52 ✓） |
| 攻角产生的横向蠕滑力 | `f22 · (v·ψ) / v` = 5e5 × 0.00052 | **260 N** |
| 轨冠倾斜的横向分量 | `N · n_y/n_z` = 59.68 kN × 0.0250 | **1 492 N** |
| 单轮横向力 | 260 + 1 492 | **≈ 1.75 kN**（实测 1.75/1.76 ✓） |
| 每轮对净横向力 | 1.75 − 1.22 | **0.53 kN** |
| **需求** | 21 842.4 N / 4 轮对 | **5 460 N/轮对** |

**差 10 倍**。接触要给出 21.8 kN，只有一条路：把接触点推到轨距角，让 `n_y/n_z` 从 0.025 长到 0.4–0.7。
实测的 `lever_y +0.9666`（轨距角）、侵入 190–200 µm、0.60 s 过冲 151 % 都是这条路的后果。

## 4 这一条是什么性质

**不是几何错、不是数值错、不是座错，而是被冻结的接触律参数值。**

* `src/velch/contact.py:317`：`linear_lateral = −f22 · slip_lateral / v` —— `f22` 的单位是 N（蠕滑系数），
  **要除以速度**才变成"每 m/s 滑移给出多少牛顿"；在 80 km/h 下 `f22 = 5.0e5` 只有 **22 500 N/(m/s)**。
* 真实轮轨单个接触斑的 `f11 ≈ 1e7 N`、`f22 ≈ 5–8e6 N`（Kalker 线性理论量级），这里两个都**低一个数量级**。
* 仓库里早已登记这一条（`docs/ARCHITECTURE_2026-10-21.md` 第 78 行、`docs/CHANGELOG_DOCS.md:4502`、
  `docs/CURVE_COROTATING_FRAME_2026-10-28.md` 第 70 行）。本轮第一次把它**量到闭合**：
  摇头 0.5 mrad 不是"没发展起来"，而是这个 `f11` 能买的力偶上限就是 1 kN·m。

因此按仓库硬约束，**不能**靠调大 `f22` 让曲线变绿 —— 那正是"提高接触刚度把失败变绿"。

## 5 那么曲线能力现在能说什么

| 能说 | 判据 |
|---|---|
| 曲线几何、放置、初始速度、座、八轮负载全部正确 | 八轮 0.988–1.013×、残差 1e-7 N、`slip_lat` 只剩攻角项 |
| 0.34 s 内七门全过、横向力达需求的 78 % | 上一轮的表 |
| 摇头平衡被量到闭合（力偶 = `k_yaw·yaw`，1 % 内） | 本文第 2 节 |
| 曲线在 0.60 s 内**不收敛**，且原因已定量 | 需要 10× 的横向力，接触只能靠贴轨距角去凑 |

| 不能说 | 为什么 |
|---|---|
| "曲线通过能力 78 %" | 那是 0.34 s 的瞬时值，0.60 s 就过冲 |
| "曲线工况可引用" | 横向状态没有稳态 |
| "18 号道岔侧向 80 km/h 的轮轨力可信" | 同上（直向 7/7 不受影响） |

## 7 顺手否掉一个"看起来显然"的修法：把蠕滑系数标定上去

既然账算出来是"横向力差 10 倍"，最直觉的修法是把 `f11`/`f22` 乘 10（`f11 = 1e7`、`f22 = 5e6`，
即真实轮轨的量级）。为此给建表脚本加了 **`--creep-scale`（只改合成算例，冻结算例一个不动）**，
记录下来以便任何引用都必须带着这个因子：

```
PYTHONPATH=src python -X utf8 scripts/s32_curved_station_table.py     --duration 0.34 --curvature-force --creep-scale 10
-> SimulationFailure: graph slope limit at axle4_right/right:main, x=22.0499317 m
```

`x` 是轨站里程（含轴偏 −10 m），所以车体只走了 **2.05 m**、t ≈ 0.09 s —— 与不放大时的 4.53 m 相比
**更早**失稳。也就是说：

> **横向力不是"不够"，而是"方向不对"。** 把蠕滑增益调大只会让同一个错方向的力来得更快。

这条否证很重要：它把"去标定 `f22`"这条看起来最省事的路**在动手之前就关掉**了。
否则下一轮很可能有人花几天把系数调到物理值，然后发现曲线崩得更早。

## 8 那么还剩什么：滚动半径差（锥度）没有出现在接触点上

继续量轮对型面本身（`case.wheels[0].profile`，282 点，y ∈ [−69.30, +70.07] mm，z ∈ [−458.0, −413.1] mm）：

```
crown at y -69.296 mm, z -413.074 mm        # 最大 z 落在型面自己的横向边界上
  wheel offset  +0 mm -> dz      +0.0 um
  wheel offset  +1 mm -> dz   -4110.3 um    # 1 mm 内掉 4.11 mm
  wheel offset  +5 mm -> dz   -9848.1 um
  wheel offset +10 mm -> dz  -14210.1 um
  +-1/2/5/10 mm: 左侧 dz 恒为 +0.0 um
```

两点：**① 型面的最高点落在它自己的边界上**；**② 从那里往一侧 1 mm 就掉 4.1 mm**（斜率 1.4），
这是轮缘/倒角那一侧，不是 1:40（斜率 0.025）的踏面锥度。而静平衡里八个接触的 `lever_z`
**完全相同（−0.42982 m）**，说明接触点落在**等半径的平段**上 —— 于是横向移动 1 mm 不会带来
滚动半径差，轮对**没有回正机制**（锥度/重力刚度都不在），只能靠 `κ v b` 那一项被摇头拉回来，
而它能给的力偶上限只有 1 kN·m（第 3 节）。

**这条是下一轮要查的对象**：型面装载后接触点究竟落在锥度的哪一段（`y_sign`/`z_sign` 与前 70 mm
裁剪的语义），以及等半径平段是不是裁掉了锥度。它属于**几何装载**问题，不是参数标定，也不是容差。
