# 接触图：摊销不可能，接线前必须先算清这笔账

日期：2026-10-21　状态：**机制已验证（四项门 PASS、单次查表 18×），但摊销测算否定了接入价值**

## 1. 单次查表确实快

| | 时间 |
|---|---|
| 直算一次接触几何 | 154.2 µs（`case_frog_N_strip05` 实测 147.8 µs） |
| 查表一次（65×81 三线性） | **8.46 µs（18×）** |
| 建一张 17×9 网格表 | 153 次直算 ≈ **23 ms** |

## 2. 摊销测算：一张表用不了几次

- 输出步 0.5 ms，350 km/h → 每步轴向前进 **48.6 mm**；内部步约 0.2 ms → **19 mm**；
- 断面站位间隔 5 mm → 同一站位在一次通过中只被用到约 **4 次**（内部步）；
- 每次省 139 µs，4 次共省 **0.56 ms**；
- 建表需 **23 ms**。

**收益/成本 ≈ 1 : 40。** 即使把建表向量化到 1 ms，仍是亏的。

## 3. 结论：不是实现问题，是架构问题

单次通行里没有任何"重复访问"可利用：

- 按站位缓存 → 每站只用 1–4 次（`profiles.py:238-287` 的区间混合让采样值逐步变化）；
- 按内容缓存 → 哈希 ≈ 省下的梯度（已实测 0.98×）；
- 按站位建位姿表 → 建表成本 40 倍于收益。

**因此不把 `map` 接成默认路径**，也不把它当作提速主线。表的价值只在"跨工况复用"时成立（同一道岔的扫参/反演批量跑，250 站建一次复用数百次）——那是**独立于本次优化的另一条线**，需要持久化表文件与版本校验。

## 4. 真正的杠杆：先把搜索域裁到接触可能区

合并网格 2144 点里，轨占 **1999 点**，但轮对横向只有 90 mm 宽、接触只可能落在其中：

- 每站一次性把轨节点裁到 `|y − 轮缘中心| ≤ 100 mm` 的带内（几何上精确，不改变结果）；
- 1999 → 约 **60 点**，梯度/插值/求和的逐元素工作量降约 **30×**；
- 与查表不同，**无需建表、无需摊销**，每步都直接受益。

这是下一步要做的实验（预切片 + 与现有结果逐位比较 + 五项门），预计接触时间从实测 147.8 µs 降到 60–70 µs 量级，墙钟 850 s → 约 500 s。
