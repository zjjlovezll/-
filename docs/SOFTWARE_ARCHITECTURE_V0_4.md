# Velch 0.4 软件架构与模型边界

## 目标

Velch 是面向车辆—轮对—道岔轨道动力学研究的独立 Python 原型。它复用 MATLAB 源码中可以核实的参数和部分接触公式形状，并把求解器、输入资源和输出契约重新组织成 Python 模块。MATLAB 不会在 Velch 运行时被调用；Simpack 的反编译线索只用于理解模型对象层级和工具边界，不能据此声称复制了 Simpack 内部求解器。

## 代码层次

```text
轮廓与里程数据
  profiles.py / simpack_track_import.py
        ↓
车辆案例契约与车辆参数
  vehicle.py
        ↓
轮轨几何与接触力                 轨道状态与模态投影
  contact.py                     track_models.py
        └──────────────┬──────────────┘
                       ↓
车辆连接器组装与时间积分
  vehicle_solver.py → solver.py
                       ↓
                  history.csv + manifest.json
                       ↑
             cli.py / gui.py
```

| 模块 | 责任 | 当前依据与边界 |
|---|---|---|
| `profiles.py` | 读取 TXT/CSV/PRR 截面、单位缩放、里程插值与异截面事件处理 | 能读几何；不会自动推断坐标变换和事件分支 |
| `simpack_track_import.py` | 只读扫描 `.spck` 引用，跟踪子模型和 PRR 路径，生成截面目录 | 提取输入几何引用；不读取 Simpack 求解器状态或生成其动态模型 |
| `vehicle.py` | 车辆参数、轮轨模板、状态向量与案例校验 | 35 个车辆广义坐标；车辆方程是独立实现 |
| `contact.py` | 截面接触候选、法向和切向接触力 | 当前采用简化图形接触、有效半径 Hertz 与有限蠕滑饱和模型；不等同于完整 SDITT、Kalker/FASTSIM 或 Simpack 接触 |
| `track_models.py` | 刚性、局部柔度与降阶模态轨道状态 | 模态输入必须由显式交换文件提供；不直接读 `.fbi/.fem` |
| `vehicle_solver.py` | 车辆、接触、轨道广义力装配，积分和 CSV/manifest 输出 | 纵向运动仍由规定速度驱动；这不是全自由度列车运行模型 |
| `cli.py` / `gui.py` | 命令行和 Tk 桌面工作台 | 调用相同的 Python 求解内核 |

## 轨道动力学选项

| `track_dynamics.kind` | 轨道自由度 | 用途 | 物理解释 |
|---|---:|---|---|
| `rigid` | 0 | 固定轨道基线或敏感性对照 | 轨道不动，轮轨反力传给地面；仍可沿里程读取不同截面几何 |
| `local_compliant`（缺省） | 每个轮轨补丁 2 个 | 现有快速原型 | 每补丁独立横/竖弹簧质量，不含钢轨连续性与相邻轮对耦合 |
| `modal` | 每个交换模态 1 个 | 独立降阶柔性轨道原型 | 模态质量、频率、阻尼和空间振型由 JSON 显式提供，接触力投影至模态坐标 |

`modal` 文件采用 `velch-modal-track-v1`：`modes[]` 中每阶包含 `modal_mass_kg`、`frequency_hz`、`damping_ratio`；`rail_shapes` 必须按案例中的轨道模板 ID 提供严格递增的 `station_m`，及形状矩阵 `phi_y/phi_z[mode, station]`。目前形状在站点之间线性插值，速度包含列车沿振型梯度运动的对流项。模态归一化、模态质量定义、坐标系与单位必须和导出来源一致，否则结果无物理可比性。

`examples/vehicle_v2/track_modes_synthetic.json` 是软件流程演示用合成数据，不可作为真实钢轨参数。要建立真实柔性轨道模型，下一步需从可信的有限元或 Simpack 授权导出物获得模态频率、模态质量/归一化、截面接触点横竖振型以及空间坐标，并做静态刚度和频响对照。`.spck` 里的轨道对象、钢轨刚体质量声明或弹性状态字段，均不足以单独重建模态动力学。

## 当前 Simpack 读取结论

针对用户给出的 H 盘分段道岔主模型，只读目录记录了 192 条截面引用、190 个唯一 PRR 文件、0 个丢失引用、5 个同里程异截面位置；这意味着 Velch 可以读入被引用的截面几何并呈现里程目录。现有目录中没有识别到模态文件引用，但这个结果只代表当前扫描范围和解析器规则，不能证明模型绝无柔性体。

Velch 不会直接读取并运行 Simpack 的刚性/柔性轨道动力学模型。当前代码不能把 `.spck` 文件转换成等价的 Velch 车辆、连接器、轨道支承或柔性体；也不能从只读 Ghidra 线索恢复专有求解器公式。对该模型，推荐工作流是：`.spck` 几何目录 → 人工确认里程分支与坐标 → 导入/校核轮廓和车辆参数 → 选择刚性、局部柔度或经标定的模态文件。

## 来源、复核和后续模块

- SDITT MATLAB 参数：`Par_Vehicle_CRH380A_v6.m` 中选取的质量、惯量和线性悬挂值；运行时不依赖 MATLAB。
- 接触：复用了可追溯到 `Multi_Con_250812.m` 的正侵入 (3/2) 次幂结构及三次饱和形式，但有效半径、阻尼、几何搜索及蠕滑简化均需单独校准。
- Simpack：对象树和批处理边界可作为格式/工作流线索；不能把它写成求解器源代码或精确车辆动力学方程。
- 下一步模块顺序：轮对与轮缘多点接触 → 齿轮/齿条啮合与分段切换 → 连续钢轨或柔性体模态数据导入 → 轨枕、扣件、垫层、轨道板支承层级 → 实测观测算子与状态反演优化器。

每个新增模型都应记录单位、坐标变换、来源文件哈希、参数来源和有效范围。只有数值求解成功不构成物理验证；与 Simpack 或试验比较前，应先对齐轮廓坐标、初始预载、工况和输出定义。
