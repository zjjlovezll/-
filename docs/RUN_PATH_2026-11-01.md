# 一条连贯的跑算例路径（第 313 轮）

用户的原话（m06836）：**"这个得包装好，之后我就只要在我的软件端口修改速度预平衡就行，你的这些都没有一个整个连贯的路径，请你排查，并将一些修改参数的端口也做好，之后我跑算例，我可以直接修改一个小参数就能跑，这个你可以借鉴 simpack。"**

这一轮交的就是这条路径。它不是新物理，是**把"改一个参数"这件事从三处手写改成一处声明**，并在起跑前把起点的状态记下来、不合格就拒绝起跑。

---

## 1. 递进的问题：原来没有路径，只有脚本

第 311 轮之前，"跑一个算例"要经过：挑一个 `cases/*.json` → 手改 `run` 块 → 写一个小脚本把它 load 进来 → 再（如果要换速度）用 `apply_speed` 打补丁 → 自己核对输出。这条链有三个断点，每一个都在第 312 轮之前是活的：

| 断点 | 表现 | 后果 |
|---|---|---|
| 换速度只改标签 | `apply_speed` 只改 `speed_profile`、`vehicle.travel_speed_m_s`、`speed_schedule`，**不动 `initial_v` 的转速** | 实测：60 km/h 行进、转速仍是 80 km/h 的 51.6796 rad/s，相对差 **0.3333** |
| 起点状态没人记 | `meta.json` 里没有 spin、没有模态起点 | 出问题时只能反推（第 310 轮花了一整轮） |
| 七门看不见起点 | 七门是数值门，不含静平衡质量与平稳性 | "7/7" 可以和"带着振动起跑"同时成立 |

所以"同一模型、只改速度就跑坏"不是模型的事：**转速没跟着改，起点没被记录，坏起点又被七门放行**。

## 2. 现在的路径：一个 setup 文件 + 八个端口 + 一次 resolve

**文件**：`setups/one_set_straight.json`（唯一一个，其余算例以后照抄）

```json
{"label": "one_set_straight",
 "case": "vehicles/turnouts/CN60-1100-1_18/cases/straight_one_set.json",
 "speed_kmh": 80.0, "duration_s": 0.02, "output_step_s": 0.0005,
 "report_launch": true,
 "prebalance": {"equilibrate_vertical": true, "seat_lateral": true,
                "seat_modal_scales": [1.0, 0.8, 0.95, 1.05, 0.5]}}
```

**端口**（`--set NAME=VALUE`，未知名直接拒绝并列出合法名、超范围直接拒绝）：

| 端口 | 单位 | 范围 | 作用 |
|---|---|---|---|
| `speed.kmh` | km/h | 0.1–400 | 运行速度；**同时决定转速** |
| `duration.s` | s | 1e-6–120 | 积分时长 |
| `output_step.s` | s | 1e-9–10 | 输出步长 |
| `report_launch` | bool | — | 是否记录起点状态 |
| `label` | — | — | 归档名 |
| `prebalance.equilibrate_vertical` | bool | — | 座椅是否解竖向平衡 |
| `prebalance.seat_lateral` | bool | — | 座椅是否把横向也解成未知量 |
| `prebalance.seat_modal_scales` | — | 必须以 1.0 开头 | 模态变形尺度的起点候选 |

**三条命令**（这就是用户要的"改一个小参数就能跑"）：

```bat
:: 只改速度
python -X utf8 scripts/s172_run_case.py --set speed.kmh=60

:: 只改预平衡（例如关掉横向座椅）
python -X utf8 scripts/s172_run_case.py --set prebalance.seat_lateral=false

:: 只看这次会跑什么，不跑
python -X utf8 scripts/s172_run_case.py --set speed.kmh=100 --dry
```

## 3. 为什么"顺序"是这一轮的核心

`velch.setup.resolve()` 做的是：**先把手上的端口写进一个新 case 文件，再 `load_vehicle_case`**。转速不是我们赋值，是 loader 从 `travel / r` 派生的，所以它不可能停在旧值上。然后 `check_kinematics` 再独立核一遍 `|spin·r − travel|/travel`，超过 1e-3 就抛错：

```
wheelset spin does not match the declared speed: |spin*r - travel|/travel = 0.333333 > 0.001.
Reload the case after changing the speed instead of patching the loaded one (velch.setup.resolve does that).
```

上面那条报文里的 0.333333 不是编的，是**故意复现**的：`tests/test_setup.py::test_patching_leaves_the_old_spin` 用旧的 `apply_speed` 打补丁，再断言这个 1/3 仍然出现、并且 `check_kinematics` 必须拒绝它。这样"改标签"这条捷径既不能被悄悄用回去，也不会被当成优化。

## 4. 实测：同一个 0.02 s，同一算例，只差"走的是哪条路"

| 运行 | 前 0.02 s 内八轨法向力最大跨度 | std |
|---|---|---|
| **旧路径**（打卡补丁，60 km/h 标签＋80 转速） | **43.573 kN** | **8.317 kN** |
| **新路径** `--set speed.kmh=60` | **0.439 kN** | **0.103 kN** |
| **新路径** `--set speed.kmh=80` | **0.417 kN** | **0.096 kN** |

三条读数各自说明一件事：

1. 同一段 0.02 s，**新路径安静 99 倍**（43.573 → 0.439 kN）——B053 就是那 43 kN 的来源；
2. 60 与 80 现在**几乎一样**（0.103 对 0.096 kN，差 7 %）——这正是"改一个参数、其余不变"该有的样子；
3. 旧路径 0.54 s 的全记录是 34.749 kN、207.753 kN 跨度（第 310 轮撤回的那趟），它不是"60 km/h 的物理"，而是"起点被踢起来之后的自由振动"。

## 5. 我自己撤回的一条判据（第 312 轮拍的）

`LAUNCH_MODAL_RESIDUAL_N = 0.1` 是我在没有测量的情况下写下的模态不平衡力门限。实测：

| 速度 | `modal_residual_n` |
|---|---|
| 60 km/h | **106.74 N** |
| 80 km/h | **101.45 N** |

并且把沉降轮数从 80 提到 **400**（每次外循环内），`|modal|` 与残差**逐位不变**（1.2471e-03 m / 101.45 N）⇒ 这不是"迭代不够"，是 `_settle_modal_coordinates` 与 `_seat` 交替的**不动点本身带 ~1e2 N**——它是"两个解器对同一个状态的折中"，与速度无关。

所以：

- **门限撤销**，常量删除；模态残差改为**上报**，并给出它占轮载的份额（**0.170 %** @80、**0.179 %** @60）；
- `balanced` 只由两条**既有**门限决定：预载残差 ≤ 0.1 N（`vertical_preload_residual` 门）、`|spin·r − travel|/travel ≤ 1e-3`（`spin_tracking` 门）；
- "这个残差要不要紧"由**平稳性审计**（`scripts/s164`，5 kN 判据）回答，不由我新拍的阈值回答。

## 6. 顺手抓到的第四个缺陷：归档标签用的是"文件里的值"

第一次跑通时，60 km/h 那趟被命名成 `one_set_straight-080.00kmh-0.0200s-500us-04c21938`——**标签 80、实际 60**，两个不同 case（sha 不同）落成同一个前缀。原因是入口把**文件里的 setup**（`setup.speed_kmh = 80`）传给了归档器，而不是**解析后**的（`resolved.setup.speed_kmh = 60`）。

已修（用 `resolved.setup` 的 label/speed/duration/output_step），并把那条错标签的归档目录与索引行一并删除（索引 66 → 65 行）。这类错误的性质是"**唯一可信的东西（名字）错了**"，比数字错更难发现，所以写进测试与文档。

## 7. 边界（这一轮没有做的事）

1. **只跑到 0.02 s**。60 km/h 的那一行读数**仍然撤回**：要恢复它必须跑到 ≥1.6 s（约 7 h）并过平稳性审计，这一轮没跑；
2. **只验证了直向"一组模型"算例**（234 维、`local_compliant`）；曲向、实测反演（`Ω_obs`）都没动；
3. **冻结物理未动**：59 680.57685863 N / 65.4661 µm / R* 0.55010 m，`freeze_baseline --check` 见提交；
4. **没改七门**。第 8 条（起点/平稳性）仍只是入口的拒绝条件与审计，不是门；把它变成门要单独一轮并先写判据；
5. **`seat_modal_scales` 仍是手写候选表**（`1.0` 永远先试）。它现在是端口，不是自动搜索。
