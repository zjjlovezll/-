# B2 事件化积分 / 峰值分辨率（2026-10-22）

目的：判断“整程峰值力”的误差到底来自**积分不密**还是**输出采样太稀**，并给出可落地的修正。

## 1. 决定性测量：峰值是采样伪影

算例 `validation/crh380a_m/case_frog_N_strip05.json`（辙叉窗，0.05 s，轴 2 右轮为峰值轮位）。

| 配置 | 积分步上限 | 输出步长 | nfev | 记录峰值 kN | 相对 5e-4 基准 |
|---|---|---|---|---|---|
| A 基准 | 1e-4 | 5e-4 | 10 253 | **208.445** | — |
| B 输出加密 10× | 1e-4 | 5e-5 | 25 697 | **213.805** | **+2.571 %** |
| C 积分加密 4× | 2.5e-5 | 5e-4 | 11 699 | 208.455 | +0.005 % |

结论：把**积分**步长缩到 1/4 只动 0.005 %（0.01 kN），把**输出**密度提到 10 倍却动 2.571 %（5.36 kN）。
⇒ 记录峰值误差几乎全部来自“峰值落在两个输出采样点之间”，不是求解器精度不足。
冲量差 1.106 %、最大侵入 154.77 / 157.64 / 154.77 µm 三点一致（侵入对采样不敏感）。

## 2. 为什么“事件检测”在这里不可能

事件法要求被检测的量是**状态的光滑函数**：`g(t, y) = N(t, y) - N_threshold`。
本模型里 `N` 不是光滑函数：

- 轮轨几何用 `argmax` 选点，接触点换面时 `∂N/∂q` 跳变（`docs/CHANGELOG_DOCS.md` 已记录 1 447 kN 类事件）；
- 辙叉融合段断面在站位间线性混合，`N(t)` 在 0.1 ms 尺度上有折点；
- 事件求解器需要 `∂g/∂y`，而现有解析雅可比在 DOP853 下**根本没被调用**（`jac_calls = 0`，见 `docs/…` 审查记录）。

因此 B2 不做“接触力阈值事件”，改为**从已接受的步重建峰值**——不引入新事件、不改积分策略。

## 3. 已实现（默认关闭）

- `RunSettings.refine_peak: bool = False`（`src/velch/model.py`，含布尔校验）。
- `src/velch/vehicle_solver.py`：`refine_peak=True` 时给 `solve_ivp` 加 `dense_output=True`，
  用 `solution.sol.ts`（**内部接受步**，不是 `t_eval`）取状态、逐点 `dynamics.evaluate` 求 `normal_force_n`，
  写入 `summary["peak_normal_force_step_resolved_n"]`；默认关闭时该字段全 0，行为与旧版逐位一致。
- 陷阱（已实测踩过）：`solution.t` 在给了 `t_eval` 时等于 `t_eval` 本身，用它重建等于什么都没做
  （首次实现峰值与输出采样完全相同 208 445.403 N）；必须取 `solution.sol.ts`。

## 4. 验证

`validation/crh380a_m/case_b2_refine_5e4.json`（输出 5e-4，`refine_peak: true`）：

| 量 | 值 | 对照 |
|---|---|---|
| `peak_normal_force_n`（输出采样） | 208 445.403 N | 与基准逐位相同 |
| `peak_normal_force_step_resolved_n` | **213 583.739 N** | +2.465 %（与加密输出 213 805 N 差 0.10 %） |
| `max_penetration_m` | 154.773 µm | 不变 |
| nfev | 11 864 | 10 253（**+15.7 %**：`dense_output` 使每步多算一次端点导数） |

`pytest` 318 passed；冻结 oracle 未受影响（`refine_peak` 默认关闭）。

## 5. 结论与使用建议

1. **报告峰值力时必须声明输出步长**：0.05 s 窗内 5e-4 与 5e-5 差 2.57 %，比模型本身很多效应都大。
2. 需要峰值时用 `refine_peak=true`（+2.47 % 准确、+15.7 % RHS），**不要**靠加密输出（+2.57 % 准确、+150 % RHS）。
3. “事件化积分提速”在本模型**不成立**：接触力对状态不可微，事件要成立必须先解决接触点换面的连续性（那是 A1/多斑层面的问题，不是积分器层面的问题）。
4. 因此 B2 的真实定位是**报告口径修正**，不是效率优化；效率的下一步仍是 A2（C–δ 简并）与 B3（表摊销）。
