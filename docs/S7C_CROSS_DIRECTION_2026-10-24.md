# S7c：横向加速度能不能把"垂向/轨向"分开——可以，但代价是条件数

日期：2026-10-24　脚本：[scripts/s7c_cross_direction.py](../scripts/s7c_cross_direction.py)（约 3 分钟可复算）

## 1. 为什么必须换实验

S7b 把横向通道加进"只激励**垂向**不平顺"的实验，结论是**什么都没变**（65.2 % → 65.1 %）。
原因不是横向通道没用，而是那个实验里根本没有横向未知量：两个带 = 两个未知量，垂向通道两行已经是
方阵，加一行只能平均噪声，而误差是偏置。

所以这一轮把未知量改成**两方向**：同一个 2.0 m 波段上，垂向幅值 `a_v` 与轨向幅值 `a_l`。
`.tre` 的 `lateral` 与 `vertical` 两列同时写入（`rail_offsets` 里 `dy = lateral + sign·gauge/2`），
两种方向各自单独激励得到一列，目标工况两方向同时存在（`a_v = 0.10 mm`、`a_l = 0.06 mm`，
刻意取不同值，这样"分不开"与"分得开但算错"能被区分）。

## 2. 结果

通道量级（(m/s²)/m，每单位轨面幅值）：

```
            被垂向激励        被轨向激励
V（轴箱垂向）   6450.5            314.0
L（轴箱横向）    572.4             33.4
```

| 观测集 | 实方程数 | 秩 | 条件数 | 复合标定误差 | 闭环 | 复原 垂向 / 轨向 (mm) |
|---|---|---|---|---|---|---|
| V（只有垂向） | 2 | **2 / 4** | — | 51.7 % | 0.78 % | +0.1005 / **+0.0003** |
| L（只有横向） | 2 | **2 / 4** | — | 48.2 % | 3.59 % | +0.1028 / **+0.0042** |
| **V+L** | 4 | **4 / 4** | **286.72** | **40.0 %** | 1.25 % | **+0.0985 / +0.0688** |
| 真值 | | | | | | +0.1000 / +0.0600 |

## 3. 读法：三个结论，一个比一个有信息

**① 结构结论（不受数值细节影响）**：单独垂向、单独横向都是 **2 秩 / 4 未知量**，
两者都把几乎全部答案放进了"垂向"槽（0.0003 与 0.0042 mm，真值 0.0600 mm）。
**这就是"只用垂向加速度分不开垂向与轨向"的定量形式**——不是精度不够，是方程不够。

**② 加了横向就分开了**：4 秩 / 4，条件数 286.72，垂向复原 **−1.5 %**、轨向 **+14.7 %**。
按任务书原来那条"分级判据"，这已经是可以对外说的东西：**横向通道把轨向从"不可见"变成"可估"**。

**③ 但复合误差 40.0 %，仍高于 30 % 门。** 两个原因都是实的：

- 条件数从 2.85 涨到 **286.72**：横向那一行比垂向弱 11–20 倍，所以它带来的信息是"贵"的；
- 更关键的一条物理事实：**在直线对称工况下，横向加速度对垂向激励的响应（572.4）比对轨向激励的
  响应（33.4）强 17 倍**。也就是说这根"横向"通道主要是被垂向几何通过蠕滑耦合驱动的，
  它对**轨向**本身并不敏感。它之所以还能把两个方向分开，是因为它对两者的响应比例与垂向通道不同，
  不是因为它是"轨向专用传感器"。

## 4. 一个必须写下来的口径问题：复合误差里含虚部残差

`relative()` 比较的是**复数**向量，而真值是实数。求解"4 个实方程"时虚部并不被约束为 0，
所以复合误差里含一部分"无法归因给实幅值的虚部残差"。

- 这一轮把两者分开报了：**复合 40.0 %，而分量实部是 −1.5 % / +14.7 %**。
- **同样的口径也适用于 S5 与 S7b 报过的 65.2 %**：那里面也含虚部残差，所以 65.2 % 应读作
  "复合意义上差 65 %"，而 2 m 带的实幅值偏差是 **−23.5 %**（这个数没变）。
  这条不是新错误，是早先没写清楚的口径；从这一轮起两份数字并列给出。

要不要把判据改成"实幅值误差"，是一个应当先定、再跑下一次的决定（否则就是照着结果改判据）。
本轮的立场：**两套都报，声明判据用复合口径（与 S5 连续），结论按分量陈述。**

## 5. 这一轮证明了什么、没证明什么

**证明了**

- 横向轴箱加速度**确实能**把垂向与轨向从"结构上不可分"变成"可估"，且轨向复原误差 14.7 %；
- 它同时**抬高条件数两个数量级**（2.85 → 286.72），因此它与"更准"不是一回事，是"可解"；
- 直线对称工况下横向通道与轨向的相关性很弱（17 倍劣势），这解释了 S7 里它的 novelty 只有 0.374
  而不是一个新坐标——**新方向 ≠ 好观测**。

**没有证明**

- 不能推广到道岔/曲线：那里左右型面不对称、有横移与侧滚耦合，17 倍这个比例会变，可能变得有利；
- 不可用来声称"实测可用"：仍是 0.10 mm 探测幅值、单一车型、单一速度；
- 0.06 mm 的轨向真值只有一次实现，没有实现间散布。

## 6. 条件数 286.72 里有 5.7 倍是量纲，剩下 50 才是真重叠

这一条是补测的，而且它把"286 太差"这个读数拆成了两半：
[scripts/s7c_conditioning.py](../scripts/s7c_conditioning.py) **重读上面那批已经跑完的运行**
（不重新仿真，约 10 秒），并从每个 `.tre` 反推激励相位重建矩阵。

| 度量 | 奇异值 | 条件数 |
|---|---|---|
| 原样 | 6483.5 / 6483.5 / **22.6** / 22.6 | **286.72** |
| 每行归一到单位范数 | 1.414 / 1.414 / **0.028** / 0.028 | **50.49** |

- 行范数：垂向行 **6458.1**、横向行 **573.4**（差 11 倍）。最小二乘对"某一行与其数据同乘一个正数"
  是不变的，但**报出来的条件数不是**。归一后有 5.7 倍消失，说明那部分是单位不齐，不是几何。
- 剩下的 50 是真问题：归一后最小奇异值 `0.028` 对最大 `1.414`，即两行的方向差不到 2°。
  这与 §3 的 17 倍比例是同一件事的两种写法——横向通道的响应几乎落在垂向通道的方向上。

**而行等比化确实改善了答案**（不是只把数字做漂亮）：

| | 垂向 (mm) | 轨向 (mm) | 轨向相对真值 | 复合误差 |
|---|---|---|---|---|
| 原样 | +0.0985 | +0.0688 | +14.7 % | 40.0 % |
| 每行归一 | +0.0989 | **+0.0613** | **+2.2 %** | 35.4 % |
| 真值 | +0.1000 | +0.0600 | — | — |

所以：**行等比化应当进估计算法**（这是最便宜的一步，不动物理、不需要新数据）；而复合误差从 40.0 %
只降到 35.4 %，说明虚部残差不是缩放问题，是"模型/测量一致性"问题，靠加权解决不了。

（写这段时我自己踩过一次：反推相位时对全零的垂向列做拟合得到相位 0，于是横向列被整体转了角度，
条件数一度上报成 110.49。脚本里已改成"取非零的那一列"，并把这个坑写在 docstring 里。）
