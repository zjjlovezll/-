# 轮对纵向自由度：让轴箱纵向通道有物理来源（2026-10-25）

## 1 为什么加

S9-6 把采样提到 20 kHz 之后，轴箱垂向加速度在短波上退化成一次除法：

```
a_box ≈ (2π f_n)² · A_rail        f_n = √(k_1/m_box)/2π = 24.86 Hz
A_rail ≈ |a_box| / 24 398
```

实测 25 / 50 mm 复原 32.9 µm 对真值 30 µm（+9.7 %）。但同一轮里 `axle1_box_left_x_acc_m_per_s2`
的谱峰是 **0.000 m/s²** —— 不是噪声小，是**这个通道在我们的模型里没有物理来源**：轮对没有纵向
坐标，`x` 由走行速度给定，蠕滑力再大也推不动它。文献里"垂向 + 纵向双通道"这条路因此无法复现。

本轮把 `x` 变成可解坐标，并量它到底看到什么。

## 2 改了什么

| 位置 | 改动 |
|---|---|
| `src/velch/vehicle_solver.py` | 新增 `self._wheel_axes`：按名字解析每个轮对的坐标下标，取代八处手写的 `wh + k`；新增 `station_m(rail, t_s, q)`：**唯一**的"这个轮子此刻在轨道哪个里程"实现，接触评估与作用-反力门共用 |
| 同上 | `x = station_m(...)`，纵向坐标参与里程；`travel = v_0 + q̇[x]` 参与蠕滑率；`creep_attack_velocity = travel · yaw` |
| 同上 | 列名：轮对纵向坐标叫 **`axle1_dx_m`**，因为写盘器最前面那四列 `axle<k>_x_m` 已经是**绝对里程**，同名会让读者把位移跟里程配到一起；`_acceleration_name` 相应给出 `axle1_dx_acc_m_per_s2` |
| `vehicles/CRH380A_M_axlebox_x.json` | 新车型：15 刚体 / **90 坐标** / 76 元件。轮对 `["x","y","z","roll","spin","yaw"]`；新增 8 根 `bearing_a{1..4}{L,R}_x`（1e8 N/m，方向 `[1,0,0]`），链条是 轮对 → 轴承 x → 轴箱 → 转臂节点 13.7e6 → 构架 → 牵引拉杆 7.88e6 → 车体 |

两条口径写进 `not_verified`，没有藏起来：

1. 1e8 N/m 的轴向轴承是**量级占位**（真实轴箱轴承轴向刚度远高于此），不是标定值；
2. 整车纵向是自由的（车体-构架只由 7.88e6 N/m 牵引拉杆相连），所以存在一个零频刚体纵向模态，
   长窗口下纵向位置可以漂移。

| 激励 | 通道 | 444.4 Hz 幅值 | 增益 (m/s²)/m |
|---|---|---|---|
| **垂向**（波磨深度） | 轴箱垂向 z | 7.937e-01 | **26 455** |
| | 轴箱纵向 x | 1.206e-06 | **0.04** |
| | 轴箱横向 y | 1.203e-01 | 4 009 |
| **横向**（轨向） | 轴箱纵向 x | 2.807e-02 | **936** |
| | 轴箱垂向 z | 1.792e-02 | 597 |

两次都是 `numerically_checked`，50 mm 波长在 80 km/h 对应 444.4 Hz，谱峰精确落在激励频率上。

## 5 机理：纵向通道量的是"滚动半径怎么变"，不是"压多深"

- 垂向不平顺在**恒定滚动半径**下不改变蠕滑率 ν = (v_x − ω r)/V，所以 F_x = f11·ν 不变 →
  纵向加速度只剩数值零点（0.04 (m/s²)/m，是 z 的 1.5e-6）。**垂向波磨对纵向通道是物理盲的**，
  不是我们模型没做完。
- 横向不平顺把接触点沿型面横移，滚动半径 r 变 → Δν = −Δr·ω/V ≠ 0 → 纵向蠕滑力被激励，
  而且它是三通道里**最强**的那一个（936 vs 597 / 382）。

于是两个短波通道各管一件事，恰好互补：

| 想知道 | 用哪个通道 | 关系 |
|---|---|---|
| 短波**深度**（波磨、擦伤、焊缝台阶） | 轴箱垂向 z | `A ≈ \|a_z\| / (2π f_n)²`，一次除法 |
| 短波**轨向 / 滚动半径变化**（轨向、多边形、偏心） | 轴箱纵向 x | 按 `Δr` 标定，量级更大 |

## 6 还没有做的

1. **解析雅可比里没有 ∂(接触力)/∂x**：里程与蠕滑率对 x 的依赖是 inexact Newton 的省略，
   与冻结几何雅可比同一类；
2. **没有做多边形/偏心算例**：那是"滚动半径变化"最直接的激励，应该给出与横向同量级的
   x 通道响应，本轮只用轨向代替；
3. **只有 80 km/h、单轴、单侧、刚性轨**；
4. 横向 200 µm 那一次的尝试是无效的：生成器只填了垂向列，`channels: ["lateral"]` 读到的是
   零——已在本轮修掉（`scripts/s9g_longitudinal.py` 现在按被测分量自己写 `.tre`），
   这类"量到一个看起来像零的零"值得单独记一笔。
