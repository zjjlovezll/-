# 曲线：把路线自己的横向速度装回去，以及为什么几何路由仍然拿不住这条曲线

日期：2026-10-28。对应目标第 4 项（曲线验收）与第 6 项（曲线反演）的前置工作。

## 1 这一轮改的四件事

| # | 位置 | 改动 | 依据 |
|---|---|---|---|
| 1 | `src/velch/vehicle_solver.py`（`curvature_1_per_m=`） | 曲率项不再按 `placement_enabled` 门控 | 曲率是**轨道**的属性：一根轴在曲线上，两个接触点走不同弧长，`±vκb` 与哪条路由无关。门控它等于让每条路由只拥有随动坐标系的一半 |
| 2 | `src/velch/vehicle_solver.py`（`_static_vertical_equilibrium` 的 `if curved:`） | 曲线时把轮对 `yaw` 加进座未知量 | `yaw` 是横向家族里**唯一不秩亏**的坐标：蠕滑律 `travel * yaw` 给它的行一个真实的刚度。`y` 与 roll 仍不进（零态轨顶接触没有横向分量 → cond 3.76e12、σ_min 2.7e-11、所有种子停在 240 kN） |
| 3 | `_align_to_track_frame`（B042） | 不再把设计线的切线写进 `yaw`，写 **0** | 状态里的 `yaw` 被蠕滑律读作**攻角**（`creep_attack_velocity_m_s = travel * q[yaw]`，`contact.py:732`），不是绝对方位。写切线等于凭空注入 `travel * arctan(slope)`：30 m 处 0.352 m/s、81.6 m 处 0.6707 m/s，足够把接触斑打到饱和 |
| 4 | 新增 `_align_velocity_to_track`（B043），在 `_integrate_vehicle` 里紧跟对齐之后调用 | 给每个刚体装上**设计线自己的横向速度**，取自 `local_state` 的第三返回值（`speed * dy_ds`） | 只摆位置不摆速度，等于让车沿直线跑而线以 0.202 m/s 横向跑掉。第一版用 `_gauge_centre` 的 1 m 差分斜率，给出 0.2121 m/s（比轨面真值 0.2020 大 5 %，因为二次曲线上的 1 m 前向差分滞后半米），这股 5 % 的外向蠕滑正是几何路由此后一直在还的账；改成取摆置本身的解析导数后逐位对齐（0.20202020 对 0.20202020） |

## 2 力路由：这一轮拿到的最干净的曲线座

`case_A_final_law` + `curve_radius_m = 1100`、无摆置、80 km/h、0.02 s、35 坐标：

```
seat residual 4.179e-08 N
axle1..4_left   59680.6 N (1.000x)  pen 65.47 um  lever_y -0.75277  n_y/n_z +0.0250  slip_lat +0.0000
axle1..4_right  59680.6 N (1.000x)  pen 65.47 um  lever_y +0.75277  n_y/n_z -0.0250  slip_lat +0.0000
sum N 477444.6 N (1.000x weight)
run numerically_checked  frames 101  gates 7/7  max penetration 66.37 um
peaks 59748..59916 N
```

八块接触斑全部落在**冻结静载门那一个数** 59 680.6 N 上，误差为 0，且 `slip_lat` 逐位为 0。也就是说：曲率进蠕滑 + 座里放开轮对 `yaw` 之后，力路由的曲线座是**精确均分**的，不是"接近均分"。

这一点必须与旧记录区分：此前（第 6 轮）力路由"八轮 59 652–59 708 N"是在**曲率没有进蠕滑**的情况下得到的，而当时几何路由八轮 0.988–1.013×。现在两条路由各自的横向账都齐了，差别只剩"轨道是否被摆到弧上"。

读法：

* 前轴的轨面在 x = 41.1989 m 处已经横移 **57.4 mm**，而车轮只到 **47.8 mm** —— 落后 9.6 mm；
* 后轴同样少了约 9–19 mm 的**正向**位移（车轮朝 +y 走得比弧线要求的少），即整车相对设计线**向外飘**；
* 触发的是 slope **1.0423**、侵入 **413 µm** 的接触点 —— 那是**轮缘**压上轨顶，不是踏面；
* 到位速度也偏了：前轴要求 0.226 m/s、实到 0.136 m/s（误差 −0.09 m/s），后轴要求 −0.178、实到 −0.318（误差 −0.14 m/s）。

## 4 为什么几何路由在无超高时注定拿不住（这一轮算清楚的一笔账）

踏面接触在 65.47 µm 侵入下给出的法向是 `n_y/n_z = ±0.0250`，每块接触斑的横向分力是

```
1.49 kN = 59.68 kN x 0.025
```

八块合计 **11.9 kN**，而 R = 1100 m、80 km/h、48 654 kg 需要的向心力是

```
m v^2 / R = 48 654 x 22.222^2 / 1100 = 21 842.4 N
```

**缺口 9.9 kN**。要补上它，车轮必须爬到型面更陡的位置（斜率 ≈ 0.2 才够），一旦爬到 1.0 就是轮缘——这就是 slope guard 在 1.04 处退出所报的事实。所以：

1. **无超高时，轨顶接触撑不住这条曲线**，这是物理，不是容差；
2. 几何路由把轨道摆到弧上之后，轨面以 `v * dy/ds` 相对车辆横向移动，车辆必须**持续**提供这 21.8 kN；而站表里**本来就是弯的**算例（18 号道岔）没有这个问题——那里的曲线是**静态几何**，没有 `rail_vy`，车轮随着前进逐站被几何引过去；
3. 这解释了为什么 18 号道岔 R = 1100 / 80 km/h 能 7/7 跑通（`seat_x_start_m = 45`、`x_start = 69`、`align_to_track` 关），而用 `curve_radius_m` 人为摆出来的同半径曲线跑不到 0.06 s。

## 5 这一轮**不**声称的东西

* 不声称几何路由"修好了"。它仍在 1.20 m 处失败，失败原因是第 4 节那笔账，不是容差；
* 不声称 B042/B043 解决了性能问题：B042 让失败点从 1.04 m 回到 1.20 m，B043 只把它从 1.20 m 前的 1.0333 m 挪到 1.1989 m（+0.17 m）。它们**清掉了两处确定性的错误**（绝对方位当攻角、位置摆了对齐而速度没摆），但没有消除第 4 节的缺口；
* 不声称曲线反演已经开始。第 6 项仍卡在"曲线跑不到 0.34 s"。
